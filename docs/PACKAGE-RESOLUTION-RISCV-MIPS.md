This is the measured source of every greyed role reason the catalog gives for riscv64 and MIPS. `studio/tests/test_package_resolution_report.py` fails if a greyed catalog reason on one of these arches cites a component this report does not mark missing.

## Method

- Command: `emerge --pretend --autounmask=n <atoms>`, with ROOT / as a native root of the measured arch, with nothing installed (an empty tmpfs over /var/db/pkg), so build, run and install time dependencies all resolve under the arch's own keywords and flags, run inside the existing builder image. Nothing is built or fetched.
- Profile: the arch's base profile stacked with `features/hardened` and `features/selinux`. Gentoo ships no hardened or SELinux profile for these arches, so the stack is assembled by the project.
- riscv64 is also measured without SELinux (the operator's 2026-11-12 decision ships it labelled "no SELinux"): features/hardened only, USE=-selinux, and every sec-policy/* atom and app-admin/setools, sys-apps/checkpolicy, sys-apps/policycoreutils, sys-apps/semodule-utils, sys-libs/libselinux, sys-apps/selinux-python left out of the role sets.
- Keywords: `<arch> ~<arch>`. A component counted missing has no keyword for the arch at all, testing included.
- Flags: USE and POLICY_TYPES from the reference platform's make.conf.tmpl; its package.use and package.mask copied in.
- Role package sets: the default install set of the nearest existing platform's role, minus board plumbing a riscv or MIPS builder replaces (listed below).
- `First missing` is the component `emerge` stopped on. `Missing top-level atoms` lists every atom of the set with no visible ebuild. `Behind it` is a second resolve with those atoms removed.
